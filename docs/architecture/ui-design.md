# UI デザイン方針

「決定 / 背景 / 棄却した選択肢」の 3 項で記録する。実装規約と再利用パーツの索引は `.claude/skills/design-system` Skill を参照。

## 1. 全体トーン: 暖色オフホワイトの SaaS

- **決定**: 背景に羊皮紙系の暖色オフホワイト（`#F4EEDE`）、強調色に深海ネイビーと黄金・錆朱・墨緑のアクセントを置く。テクスチャや装飾 SVG は使わずフラットなサーフェスで構成する。
- **背景**: 「家族・恋人と行きたい場所を共有する」という親密でゆるい体験には、純白の冷たい SaaS より少し暖かい紙色が合う。一方で装飾性が高すぎると操作の主役を奪い、ちかちかとした明暗差が出るため、装飾は色トークンに留めて面はフラットに保つ。
- **棄却した選択肢**:
  - **Vintage Map（紙の質感・等高線・コンパスローズ・カテゴリピン突き出し）**: 一度試したが、複数の面が異なる明度で重なってちかちかし、SaaS の操作体験から遠かった。色トークン（parchment / deep-sea / gold / rust / moss）と要所のコンパスアイコンだけ残し、ノイズ・等高線・装飾 SVG は撤去した。
  - **純白 + ダークグレーの一般 SaaS**: 親密さが出ず、家族で共有する場のトーンに合わなかった。

## 2. サーフェス: `surface` に一本化

- **決定**: カード面は `.surface`（旧 `.paper-card`）クラス一本に統一する。`bg-content1` 系のオフホワイト + 1px の薄い枠線 + ごく弱い影で表現する。テクスチャレイヤー（`::before` の等高線）は持たない。
- **背景**: 「面の上に面が乗る」表現が複層化すると明暗差が増えてちかちかする。SaaS の基本構図は本体背景 → カード面 → カード内入力面の 3 段で十分。`bg-content2` の入力枠で 1 段だけインセットを表現する。
- **棄却した選択肢**:
  - **paper-card の装飾レイヤー (等高線 ::before)**: ノイズが多く、文字の上に重なって可読性も落ちた。
  - **影だけでカードを浮かせる枠線レス構成**: 暖色ベースだと影が黄色く濁って見えるため、薄い枠線で輪郭を支える構成に戻した。

## 3. ヘッダー: sticky + backdrop-blur

- **決定**: `AppHeader` を全ページ共通の sticky フローティングヘッダーとし、`backdrop-filter: blur` で背景を透過させる。中央に置く「wanna-go」ロゴ + 小さなコンパスは識別子としてのみ機能。
- **背景**: 縦長になりがちなブックマーク一覧で常にナビゲーション（ホーム導線・グループ ID 表示・設定ボタン）にアクセスできるようにする。透過させることで縦移動中も視覚的に存在感を出しすぎない。
- **棄却した選択肢**:
  - **非 sticky の通常ヘッダー**: 一覧が長くなると戻り導線が遠くなり、グループ ID も常時参照できない。
  - **不透明なヘッダー**: 紙色の本体背景と分離して見え、SaaS の一体感が弱かった。

## 4. ブックマークカードの情報密度とアクション

- **決定**: ブックマーク一覧は 2 カラムグリッドの surface カード。1 枚あたりの情報優先順位を次のとおりに固定する。
  1. 左 1px の色帯 + カテゴリ絵文字 + カテゴリ名 + 興味度ドット（メタ情報の帯）
  2. OG 画像（あれば、16:9）
  3. タイトル（`font-display`、訪問済みは取り消し線）
  4. メモ → 住所 → テーマチップ → URL（小さく truncate） → 訪問日
  5. 主アクション「訪問済みにする / 未訪問に戻す」（フッター幅広ボタン）
  - 補助アクション（編集 / マップで開く / 削除）は右上の `⋯` Dropdown に集約する。
- **背景**: 1 タップで使う頻度が圧倒的に高いのは訪問状態の切り替え。残りは編集系で頻度が低い。4 つのボタンを横並びにすると主従が曖昧になり、削除ボタンの誤タップ事故も増える。
- **棄却した選択肢**:
  - **左上のピン突き出し**: カードが付箋紙風になりインパクトはあるが、カード端のクリック領域を阻害し、グリッド時に列がガタつく。色帯 + インラインピル表示に置き換えた。
  - **訪問済みドット + 4 ボタン横並び**: 訪問状態が小さすぎて気づかず、削除ボタンが間違ってタップされる事故が発生した。

## 5. 進捗の可視化: 線形プログレスバー

- **決定**: `ProgressGauge` は「ラベル + 数値 + 線形プログレスバー」の単一カードとする。半円メーターや時計型は使わない。表示する指標は「訪問数 / 総数」と「達成率（%）」の 2 つに限定する。
- **背景**: 半円メーターは装飾性が高い反面、SaaS では数値が読み取りにくい。線形バーは進捗の意味が即時に伝わり、複数並べても破綻しない。
- **棄却した選択肢**:
  - **半円ゲージ + 針アニメーション**: Vintage Map 期に採用したが、SaaS 化で線形バーに置き換え。
  - **平均興味度の併記**: ブックマーク群の平均は意味が抽象的で、画面の視認情報量を増やすだけだった。表示しない。

## 6. フィルタ UI: 検索バー + 訪問状態セグメント + カテゴリ pills

- **決定**: 一覧フィルタは縦 2 段で組む。上段は全幅の検索バー、下段は「訪問状態の 3 値セグメント（すべて / 未訪問 / 訪問済み）」と「カテゴリ pills（全カテゴリ + 各カテゴリ）」を左右に並べる。Select のドロップダウンは使わない。
- **背景**: ドロップダウンは現在の状態がひと目で分からない。セグメント / pills なら開かなくても何で絞っているか即分かる。カテゴリ数が固定 5 種類で pills 化が現実的。
- **棄却した選択肢**:
  - **HeroUI Select を 2 つ並べる**: 開閉が必要で、選択中の値を視認する手数が増える。
  - **チップ群を 1 段に詰め込む**: 訪問状態とカテゴリの粒度が混ざり、判断が複雑になる。

## 7. ブックマーク登録フォーム: 3 カード構成

- **決定**: 登録 / 編集フォームは「URL から取得」「場所を選ぶ」「詳細」の 3 枚の `surface` カードで構成する。上 2 枚は横並び（モバイルは縦）、下 1 枚は単体。各カードは「アイコン + 見出し + ヘルプテキスト」の共通ヘッダー様式を持つ。
- **背景**: 想定ユースケースは「URL だけで登録」「場所だけ Maps から登録」「URL も場所も両方ある」の 3 通り。フィールドを縦に並べると「どこから始めればいいか」「どっちが必須か」が伝わらなかった。並列カードで両方が独立した開始点であることを明示し、両方使ってもよいことをラベルで示す。
- **棄却した選択肢**:
  - **タブ式（URL から / 場所から）**: 片方しか使えないように見え、「URL も場所も両方持っている」ユースケースが排除されているように見えた。
  - **LocationSearch を最上部に縦並び**: 場所検索が主役のように見え、URL 単独登録の動線が分かりづらかった。

## 8. 詳細カードのフォーム言語

- **決定**: 詳細カード内のフィールドはすべて HeroUI 公式 API（`label` + `labelPlacement="outside"`）で記述し、ラベル様式を統一する。興味度は `Slider` の `label` + `getValue` を使い、自作の `<label>` や数値スパンを併用しない。入力背景は `bg-content2` で揃える。
- **背景**: 「興味度のラベルが唐突」というフィードバックの原因は、興味度だけ自作 label で他のフィールドと位置・サイズ・色が異なっていた点にあった。公式 API に乗せれば自然に揃う。
- **棄却した選択肢**:
  - **興味度を星評価のクリック UI に置き換え**: 検討余地はあるが、他のフィールドと様式を揃える目的では Slider のままが整合的だった。

## 9. 共有 UI: フラット ID + URL + QR

- **決定**: `group-settings` の共有セクションは「グループ ID（大判 mono タイポ + コピーボタン）」「共有 URL（コピーボタン）」「QR コード（120px 程度の小ブロック）」を 1 枚の surface に並べる。Web Share API があれば「共有」ボタンでネイティブシートに繋ぐ。
- **背景**: ID と URL と QR は共有の 3 経路で、どれを使うかは相手と状況で変わる。並置することで状況に応じて選べる。
- **棄却した選択肢**:
  - **羊皮紙風の招待状カード（透かしコンパス・大判 ID・点線縁）**: Vintage Map 期の実装。SaaS 化で装飾を撤去し、機能優先の並置に再構成した。

## 10. アニメーション方針

- **決定**: 動きは「カード初出の pin-drop（短い fade + 上から下へ）」「カードホバーの 1px lift」「訪問チェックの ink-check（stroke-dashoffset）」「ローディング時のスピン」のみ。`prefers-reduced-motion: reduce` で全部無効化する。
- **背景**: SaaS では強い装飾アニメは集中を奪う。重要な状態変化（訪問チェック）だけ目に残るように、他は控えめにする。
- **棄却した選択肢**:
  - **AnimatePresence によるページ遷移演出**: 遷移中の体感が遅くなり、操作のテンポを損なう。導入しない。
  - **コンパス針のアイコン回転を興味度スライダに連動**: Vintage Map 期に試したが、SaaS では装飾過剰で削除した。
